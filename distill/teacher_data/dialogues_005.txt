def is_palindrome(s):

def average(nums):

### mt/p006 | skills=code_algorithm
@user
Write a function that returns the nth Fibonacci number.
@assistant
I'll use the convention fib(0) = 0, fib(1) = 1, and each later number is the sum of the two before it.

```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

The loop keeps the last two numbers and moves them forward n times. For n = 10 it returns 55.
@pyassert fib(0) == 0 and fib(1) == 1 and fib(10) == 55
@user
My teacher showed a recursive version. Why didn't you use that?
@assistant
The recursive version follows the definition closely, which makes it good for teaching:

```python
def fib_recursive(n):
    if n < 2:
        return n
    return fib_recursive(n - 1) + fib_recursive(n - 2)
```

Its weakness is speed. Each call makes two more calls, and the same values are recomputed again and again. `fib_recursive(30)` already makes over a million calls, and each increase of n by one multiplies the work by about 1.6. The loop does n steps and nothing more.
@pyassert fib_recursive(15) == 610
@user
Can I keep the recursion but make it fast?
@assistant
Yes, by remembering results that were already computed. This is called memoisation, and Python has a ready-made decorator for it.

```python
from functools import lru_cache


@lru_cache(maxsize=None)
def fib_memo(n):
    if n < 2:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)
```

Each value of n is now computed once and then read from the cache, so the work grows in step with n, as it does in the loop. One limit remains: very large n, around a thousand or more, can hit Python's recursion depth limit, which the loop version never does.
@pyassert fib_memo(80) == 23416728348467685
